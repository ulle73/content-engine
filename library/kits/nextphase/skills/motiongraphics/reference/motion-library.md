# The motion library — 17 devices

Learned frame-by-frame from four reference grids and rebuilt in this skill's tokens.
Open `components/mg-motion-library.html` in a browser to see them all animate; append
`?still` semantics are not needed there — use the **Hold at settled** button.

**These are devices, not scenes.** `layouts.md` defines the ten scene *layouts* a beat
can be built in; this file lists the *motion units* that fill them. A Slam Card might use
the orb count-up; a Diagram Takeover might use the goals list; a Clean Face beat might get
a notification pile-up floating over it.

> **Sources** — four 2×2 grids, each quadrant a separate animation, split and sampled at
> 4fps: `U7gSizSj_ME` · `2p6DzWHPGgU` · `_I48er2ckk0` · `EF0zycDs8MU`.
> The originals run a slightly muted purple (`#9C48B4`, `#784890`, `#241878`) — the same
> family as ours a touch desaturated, so restyling onto `--mg-violet` is a straight swap.
> The originals also use a squarish techno display face; we deliberately render in
> `--mg-font-slam` instead, because house type outranks source type.

## The devices

| # | Device | Class of beat | The mechanic that matters |
|---|---|---|---|
| 01 | **Cursor card** | UI / demo | A cursor moves in, **hovers, clicks, and the card dismisses**. The click is 3f down, 4f back. |
| 02 | **Tag cloud** | entrance | Pills fly in **from alternating sides under heavy directional blur**, then settle. |
| 03 | **Blur swap** | text | One label becomes the next **through blur — 4f out, 4f in**. Never a crossfade. |
| 04 | **Wave journey** | chart | A filled wave **undulates continuously** while pin markers ride its surface. |
| 05 | **Goals list** | list | Rows accumulate word by word while the camera **pushes IN**, so early rows leave frame. |
| 06 | **Ladder climb** | metaphor | A marker climbs rung by rung, then the ladder **shears away**. |
| 07 | **Aurora floor** | ground | A perspective wireframe floor with drifting aurora. Loops forever. |
| 08 | **Alert flash** | the turn | Real media + slam headline, then **tint and glow flip to alert together**. |
| 09 | **Bloom question** | hook | Accumulating text on a **blown-out light field** — dark text on bright ground. |
| 10 | **Orb count-up** | stat | A number counts **inside a growing sphere**, halftone field resolving behind. |
| 11 | **Skeleton fill** | reveal | **Empty rows fill one at a time**; the last lands as the highlighted result. |
| 12 | **Chip marquee** | band | A rail of glossy chips **scrolling continuously**, seamless via a doubled pass. |
| 13 | **Countdown swap** | text | Numeral **and** label both blur-swap: 3 → 2 → 1. |
| 14 | **Orbit hub** | diagram | Satellites orbit a labelled sphere, **z-order flipping** as they pass behind. |
| 15 | **Notification pile-up** | proof | Items stack in; **the shell lands first, the text fills after**. |
| 16 | **3D numbered grid** | list | A two-column list builds, then the whole grid **tilts into perspective**. |
| 17 | **Chat count-up** | proof | A **light** pill on the dark stage — the style's one inversion — with a counting badge. |

## What these added to the system

Five grounds and materials came out of this study and now live in `assets/tokens.css`:

- **`.mg-bg-floor`** — the perspective grid floor with aurora. The converging lines are
  **real SVG geometry**, generated by `buildFloor()`. Two traps, both hit during the
  build: a CSS-gradient grid under `perspective() rotateX(72deg)` compresses to nothing
  and renders no lines at all; and a 1.4px stroke anti-aliases away entirely when the
  stage is previewed at ~0.3 scale. **Keep the stroke at 3px.**
- **`.mg-bg-blowout`** — the blown-out light field. The one place this style goes bright,
  and the only place text on a ground is **dark rather than white**.
- **`.mg-bg-vortex`** — near-invisible drifting rings; gives a still stack something to
  sit against without competing.
- **`.mg-dots`** — halftone field, masked open at the centre so a hero object sits in
  clear air.
- **`.mg-rays`** — radial speed lines (children generated in JS).
- **`.mg-ghost`** — the giant ghosted wordmark watermark, ~4.5% opacity. Any more and it
  competes with what sits on it.
- **`.mg-numeral`** — the glass numeral badge. Set `--nsz` for the numeral size.
- **`.mg-orb`** — the glowing sphere; holds a count-up, a label, or nothing.
- **`.mg-cursor`** — the pointer, always a drawn SVG arrow. Never an emoji, never a
  system cursor glyph.
- **`--mg-alert` / `--mg-alert-deep`** — **semantic only**, deliberately off the violet
  ramp so it can never be read as brand colour. The alert-flash device and nothing else.

## Rules these devices follow

Everything here obeys the existing motion grammar; three points are worth restating
because this set leans on them hard:

1. **Blur is the transition, not a crossfade.** Devices 03 and 13 swap text by blurring
   out over 4 frames and back in over 4. A dissolve between two words reads as a
   different, softer style entirely.
2. **The shell lands before the content.** Devices 11 and 15 both put an empty container
   on screen first and fill it after. That gap is what creates anticipation; a card that
   arrives complete has no second beat.
3. **A camera move beats an element move.** Devices 05 and 16 move the *camera* — a
   push-in, a tilt into perspective — rather than animating each row. Same rule that the
   diagram takeover gets wrong most often (`motion-grammar.md`).

## Combining them

One device per beat. Two is a collision, not a composition — the exception is a **ground**
(07) plus one device on top, which is how they are meant to be used.

Reach for the catalog first where one exists (`catalog-map.md`): `count-up`,
`notification-pileup`, `simulated-cursor`, `marquee`-style bands and `flowchart` blocks
all overlap with devices here and arrive with more polish than a hand-build. These
implementations exist so the *look* is pinned when you do need to hand-build.
